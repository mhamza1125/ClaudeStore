Current repository state:

Confirmed business and technical decisions (do not ask again):
- Brand name: "Atelier Hide" (a demo placeholder, configurable from admin settings and config/brand.php).
- Base currency: USD. Store all money as integer minor units (cents). Other currencies are informational only for now.
- Database: MySQL 8 in local and production use (DB name "claudestore"; local dev uses root with no password). Keep migrations database-agnostic so the test suite can also run on SQLite in-memory when MySQL is not available (for example in a cloud sandbox).
- Admin panel: a custom Livewire 3 + Blade + Tailwind admin. Do NOT use Filament (too slow for this project).
- Stack: Laravel 12, Livewire 3, Alpine.js, Tailwind CSS v4 (Vite), Laravel Fortify for authentication, spatie/laravel-permission for roles, barryvdh/laravel-dompdf for PDFs, intervention/image for image optimisation, the database queue driver, the local/public disks with S3 configurable through env.
- Roles: super-admin, admin, sales-rep, customer.
- No payment gateway. Accepted quotes are converted to sales orders and handled offline.
- Mail uses the "log" driver in development; SMTP is documented for production.
- Tax and shipping are flat rates from admin settings, overridable per quote.
- Seed a development admin account (admin@atelierhide.test) and print its password in the seeder output (development only).
- Pricing precedence: (1) company-specific negotiated price (variant, then product), (2) customer-group tier price, (3) product/variant quantity tiers (variant tiers override product tiers), (4) variant base price, then product base price. Document this in docs/PRICING.md.
- Quote reference format: AH-Q-YYYY-000123.

Git workflow:
- Commit after each completed phase with clear messages, so progress is never lost.

Light and dark theme (required)

Support both a light theme and a dark theme across the storefront, customer portal, and admin panel.

- Light theme: warm cream/ivory backgrounds, espresso and chocolate text, brass accents.
- Dark theme: deep espresso/near-black backgrounds (not pure #000), warm ivory text, slightly brighter brass accents. It should still feel like premium leather, not a generic dark UI.
- Define every color as a semantic design token (for example --color-bg, --color-surface, --color-text, --color-muted, --color-border, --color-accent) using CSS custom properties with Tailwind v4 @theme, and switch the token values with a "dark" class on <html> (Tailwind's class-based dark variant). Components must use tokens, not hardcoded colors.
- Add a theme toggle in the storefront header, customer portal, and admin top bar with three options: Light, Dark, System. Default to System (prefers-color-scheme).
- Remember the choice in localStorage (wrapped in try/catch). For logged-in users, also save it on the user record (a "theme" column) so it follows them across devices.
- Prevent the flash of the wrong theme: apply the theme class with a small inline script in <head> before CSS loads.
- Check color contrast in both themes (WCAG AA for text), and check that product images, form fields, tables, badges, modals, and focus states look correct in both.
- Emails and PDF quotations stay in the light brand theme.

4. Core requirement: B2B quantity-based pricing

This is one of the most important features.

Build a configurable wholesale pricing engine.

Example pricing for a hypothetical leather wallet:

Order quantity	Unit price
1–24 units	$18.00
25–99 units	$15.00
100–249 units	$12.50
250+ units	$10.00

These are illustrative seed-data values only. All prices and thresholds must be editable through the admin panel.

When the customer changes the quantity, update the applicable unit price, subtotal, and total immediately.

Example:

Quantity: 10 → unit price $18.00
Quantity: 50 → unit price $15.00
Quantity: 150 → unit price $12.50
Quantity: 300 → unit price $10.00

The frontend can calculate a preliminary display, but the server must always recalculate and validate prices before saving a quote or order.

Support:

Minimum order quantity (MOQ)
Minimum order value, if configured
Quantity-based price tiers
Product-specific pricing
Variant-specific pricing
Customer-group pricing
Negotiated customer-specific pricing
Optional volume discounts
Optional price-on-request products
Optional case-pack or order-multiple rules
Currency configuration
Configurable tax treatment
Configurable shipping charges

Define clear pricing precedence, for example:

Customer-specific negotiated price
Customer-group price
Product quantity-tier price
Default product price

Document the final precedence rules and make them consistent throughout the application.

When a buyer changes the quantity, show the applicable price tier clearly. If the new quantity crosses a price threshold, update the display without requiring a page reload.

Support mixed-product quotations. Each product line should use its own applicable price rules unless a separately configured cart-wide discount applies.

Keep money calculations precise. Do not use floating-point arithmetic for financial calculations.
